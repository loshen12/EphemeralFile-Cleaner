# PRD — EphemeralFile Cleaner 产品需求文档

> 版本：v2.0（2026-08-22）｜替代原 dev.md v1.1 的需求部分
> 文档体系：PRD（本文，业务需求）→ Spec.md（技术方案）→ Plan.md（开发计划）
> 本文只描述业务需求、规则与边界，不含技术实现细节。

## 1. 产品概述

跨平台（Windows / macOS / Linux）的一次性/临时文件清理命令行工具。以**任务**为单位组织清理：一个任务 = 目标目录 + 一组文件名匹配规则（正则）。任务可持久化为**长期任务清单**反复执行，也可每次执行时一次性指定。命中的文件在删除前自动备份，然后移入**系统回收站**（绝不物理删除）；高危目录需二次确认；按小批量分批推进，全程留有备份清单与执行日志等审计记录。

同时服务两类使用者：

- **人类用户**：命令行交互（确认、预览、总结）与交互式会话（REPL）；
- **Agent/自动化**：无头调用——一行结构化结果、严格退出码、参数可经管道传入、全程无阻塞。

## 2. 目标与非目标

**目标**

- 安全第一：任何删除都可追回（回收站 + 删前备份 + manifest 审计 + 执行日志）；
- 每次执行必须明确「目标路径 + 匹配规则组」，杜绝误扫误删；
- 长期任务清单 + 默认任务清单，日常清理一条命令完成；
- 三平台一致的安全语义（保护目录、卷根、批量上限、退出码）。

**非目标（本期不做）**

- `efc restore`：按 manifest 自动恢复——列入 Roadmap，当前从备份目录手工拷回；
- 定时/后台自动清理（schedule/watch）【待复核：是否有此需求】；
- 清理后留下的空目录保持原样，不做目录删除；
- 备份文件的保留时长与自动清理策略【待复核：暂由用户手工管理】。

## 3. 用户场景

| 场景 | 用法 |
|---|---|
| 一次性预览 | 指定目录与规则，列出将命中的文件（只读，不删） |
| 一次性清理 | 指定目录与规则，走确认 → 备份 → 回收站全流程 |
| 日常例行清理 | 预先把常用目录+规则保存为任务并标记默认，之后一条命令执行默认任务清单 |
| 管理任务清单 | 命令行增/删/查任务（纯配置操作，不扫描不删除） |
| 查看当前规则 | 列出任务清单中各任务的匹配规则 |
| 交互式会话 | 逐步设置目录/规则、预览、清理（会话内调整不落盘） |
| Agent 调用 | 单行 JSON 结果 + 退出码判定成败；大量参数走管道输入 |

## 4. 功能范围

### 4.1 命令组

| 命令 | 用途 |
|---|---|
| `scan` | 只读预览：逐任务列出将命中的文件 |
| `clean` | 执行清理：安全门 → 扫描 → 确认 → 备份 → 分批入回收站（按任务循环） |
| `repl` | 交互会话：task / dir / pattern / recursive / list / clean / status / help / exit |
| `task add / list / remove` | 维护长期任务清单（纯配置操作，不扫描不删除） |
| `patterns` | 列举任务的匹配规则（只读） |

### 4.2 任务清单（核心概念）

- 任务的属性：**名称**（清单内唯一）、**目标目录**（必须存在）、**匹配规则组**（文件名正则，任一命中即匹配）、**递归开关**、**默认执行标记**；
- **默认任务清单**：带默认执行标记的任务按配置顺序构成；`scan`/`clean` 不带任务参数时自动执行它们；
- 同名重复保存 = 更新该任务（规则默认追加去重，可选整体替换）；
- 每次执行必须明确本次任务，来源与优先级：**指定任务名（可多个）> 全部任务 > 一次性指定目录+规则（不落盘）> 默认任务清单**；一次性指定与指定任务名/全部任务互斥；
- 完全没有可用任务时明确报错并提示如何创建任务。

## 5. 业务规则

### 5.1 安全规则（红线，任何情况不可妥协）

1. **平台限制**：仅支持 Windows / macOS / Linux，其他平台拒绝运行；
2. **回收站而非永久删除**：删除文件的唯一去向是系统回收站；全项目禁止任何形式的永久删除操作；
3. **网络路径**：Windows 网络路径（UNC）直接拒绝；macOS/Linux 网络挂载点视为高危目录，其上删除失败按失败文件计（不会物理删除）；
4. **卷根一律高危**：盘符根（`C:\`）、`/`、各挂载点视为高危，须二次确认；
5. **高危目录二次确认**：目标是系统保护目录、位于其内、（递归时）是其祖先、或等于用户主目录时，必须**逐字符输入完整目标路径**才能继续；`--yes`、管道环境均不可绕过；非交互环境遇高危直接中止（失败安全）；
6. **删前备份**：默认开启；单文件备份失败则跳过该文件（记录在案、不删除），绝不"先删后补"；
7. **小批量 ≤ 10**：每批删除文件数上限 10，配置越界直接报错（不是截断）；交互模式下批与批之间需确认继续；
8. **只删文件，不动目录**；空目录保持原样；
9. **不跟随符号链接/junction**；
10. **默认需要确认**：非终端环境且未显式跳过确认时，需确认的场景直接中止（绝不静默执行）；
11. **Agent 契约**：无头模式下标准输出只允许一行结果 JSON；业务失败绝不返回成功码；非交互全程不得等待用户输入。

### 5.2 确认与交互规则

- 普通确认（删除前列出命中文件，询问是否继续）默认开启，可显式跳过——但跳过确认**不能**绕过高危二次确认；
- 高危确认要求输入大小写归一化后的完整路径，一次不匹配即中止；
- 批间确认：第一批后每批开始前询问"继续下一批"，拒绝则停止（已删不回滚）；
- 交互式会话中：目录指向高危时当场警告；非法规则当场拒绝并不进入清单；单条命令出错不会崩掉会话。

### 5.3 退出码契约（硬契约）

| 码 | 含义 |
|---|---|
| 0 | 成功（含"0 命中，无事可做"） |
| 1 | 未预期内部错误 |
| 2 | 配置/用法/输入错误（含不支持平台、网络路径、坏规则、任务/目录不存在、参数互斥、非法输入） |
| 3 | 用户中止 / 安全拦截（拒绝确认、高危未通过、非交互遇高危） |
| 4 | 执行期部分失败（存在备份失败或回收站失败的文件） |

多任务执行时：任一任务有失败文件 → 4；否则任一任务被中止 → 3；否则 0。

### 5.4 Agent 模式（业务契约）

- 全局开关：输出格式（text/json）、非交互、stdin 输入，须位于子命令之前；
- 输入优先级：**命令行显式参数 > stdin JSON > 环境变量 > 配置文件 > 默认值**；同键整体覆盖（列表不合并）；
- 传输级开关只来自命令行与环境变量，不来自 stdin 负载；
- stdin 只允许非终端环境使用（防挂起）；负载只含业务参数，未知字段直接报错（严格输入）；
- json 模式下人类可读信息（表格/进度/警告）一律走标准错误或静默；跳过确认自动通过，但高危仍直接中止；
- 交互式会话（repl）不支持 Agent 模式，带上任一 Agent 开关即报错。

### 5.5 备份与审计

- 删除前把全部命中文件按原目录结构复制到备份目录（每次运行独立时间戳子目录）并写 manifest（含每个文件的原路径/备份路径/状态/大小）；
- 删除前做备份空间预检：可用空间不足则整体中止（绝不先删后失败）；
- 每次清理（含干跑与中止）追加一条执行日志：含具体文件名、大小、命中规则、状态、结果分类与用时；
- 备份目录/日志文件位于目标目录内时，扫描自动排除（防止清掉自己的备份/日志）；
- 备份会复制全部待清理文件——敏感数据场景应在 README 中提示风险与建议。

### 5.6 清理总结

每次 clean 结束后输出总结：按**任务 → 命中规则**两层汇总（只统计实际入回收站的文件）；多任务时按执行顺序编号分节；有失败文件时在末尾单独提示。匹配语义说明：对**文件名**做子串正则匹配（非全路径）。

## 6. 边界场景

| 场景 | 期望行为 |
|---|---|
| 0 命中 | 输出提示，成功退出（码 0） |
| 单文件备份失败 | 跳过该文件（记录），继续其余，最终码 4 |
| 单文件入回收站失败 | 记录失败，继续其余，最终码 4 |
| 批间拒绝继续 | 停止后续批次，已删不回滚，码 3 |
| 备份空间不足 | 删除开始前整体中止，码 3，零删除 |
| 高危 + 非交互/json | 直接中止，码 3 |
| Windows 网络路径 | 拒绝，码 2 |
| 任务名不存在 / 目录不存在 / 坏正则 | 码 2，保存类操作不落盘 |
| 无任何任务可用 | 码 2，提示创建任务的方式 |
| stdin 在终端环境使用 | 码 2（防挂起） |
| stdin 负载含未知字段/类型不符 | 码 2 |
| 执行日志写入失败 | 仅警告，不影响清理结果与退出码 |
| 无权限遍历的子目录 | 跳过并计数，不中断 |
| 空任务清单查询规则 | 空提示，码 0（查询成功） |
| repl 未知命令 | 打印帮助提示，不退出会话 |
| 重复保存同名任务 | 更新（规则追加去重或整体替换） |
| 旧版顶层默认目标字段出现在配置中 | 报错（码 2），提示改用任务清单 |

## 7. 平台差异（业务影响）

| 维度 | Windows | macOS | Linux |
|---|---|---|---|
| 回收站 | 系统回收站 | Finder 废纸篓 | freedesktop Trash |
| 删除失败行为 | 网络卷可能**物理删除**（故 UNC 入口拒绝） | 抛错计为失败，不物理删除 | 抛错计为失败，不物理删除 |
| 无桌面环境 | — | 纯 SSH 会话可能失败（码 4） | 无 trash 服务组件时失败（码 4） |
| 文件名大小写 | 不敏感 | 默认不敏感 | **敏感**（忽略大小写开关语义有差异，按任务配置） |
| 内置保护目录 | 系统目录（Windows/Program Files/ProgramData 等） | /System、/Library、/usr、/Applications 等 | /、/usr、/etc、/var、/boot 等 |

用户主目录**本身**视为高危；其内部子目录不自动高危（跨平台下用户目录是常规清理对象）。

## 8. 验收清单（业务口径）

- 三平台安装后基础命令可用；其他平台拒绝运行；
- 对临时目录真实清理：文件进回收站、可从备份+manifest 对账、全程无永久删除；
- 高危目录必须重输完整路径才能继续，任何自动方式无法绕过；
- 批量上限越界被拒绝；13 文件按 5/批 分 3 批；
- 任务清单增删查正确；默认任务清单一条命令执行；同名更新/去重/整体替换正确；
- 清理总结按任务→规则分层；执行日志含具体文件名；
- Agent 模式：单行 JSON 结果、退出码严格一致、非交互无阻塞、高危返回 3；
- repl 与命令行走完全相同的清理流程（行为一致）。
